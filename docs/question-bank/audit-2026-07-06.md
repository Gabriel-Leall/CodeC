# Kodan Question Bank Audit

Data: 2026-07-06

## Escopo

Audit manual do sistema de perguntas do Kodan, com foco em:

- estrutura do `question-bank`
- ponte entre seed editorial e desafio jogavel
- aderencia da documentacao ao que o codigo realmente faz
- preparo do projeto para autores humanos e IA

## Como o audit foi feito

- Leitura direta do codigo em `scripts/question-bank/`, `content/challenges/` e `packages/db/src/`
- Comparacao do material gerado com o runtime atual
- Inspecao da documentacao existente

Observacao:

- A skill local `impeccable` nao estava operacional no projeto porque `.impeccable/` so continha `design.json`, sem os scripts e referencias exigidos pela propria skill.
- O audit, portanto, foi feito pelo estado real do repositorio e nao por automacao dessa skill.

## O que ja esta bom

- O Kodan ja possui um `question-bank` separado do runtime.
- A fonte de verdade editorial esta em `scripts/question-bank/bank-data.ts`.
- O corpus minimo ja existe e esta balanceado:
  - 50 seeds de TypeScript
  - 25 seeds de React
- Os tres tipos de pergunta ja estao modelados no toolkit:
  - `debug`
  - `explain-code`
  - `explain-concept`
- O runtime de desafios ja aceita `type` livre e aplica default seguro quando ele nao existe.

## Gaps encontrados

### 1. Drift entre codigo e documentacao

- `content/challenges/README.md` ainda mostrava `type: "find-bug"`, mas o runtime atual trabalha com `debugging`.
- O `README.md` raiz ainda descrevia o repositorio quase como template generico, sem explicar o fluxo de perguntas do Kodan.

### 2. Conhecimento editorial preso no codigo

- O checklist por tipo de pergunta existia apenas em `bank-data.ts`.
- Isso dificultava reuso consistente por IA, por humanos e por futuras promocoes para runtime.

### 3. Falta de template oficial

- Havia seeds geradas, mas nao havia um template unico, claro e copiavel para criacao de novas seeds.

## Decisoes tomadas nesta rodada

- Centralizar o checklist canonico por tipo de pergunta no toolkit.
- Documentar explicitamente o mapeamento entre `challengeType` da seed e `type` do runtime.
- Gerar documentacao derivada para reduzir novo drift.
- Criar um template de seed pensado tanto para IA quanto para autores humanos.

## Estado esperado apos esta rodada

- `content/question-bank/README.md` passa a explicar melhor tipos e fluxo editorial.
- `docs/question-bank/authoring-guide.md` vira o guia canonico de autoria.
- `docs/question-bank/seed-template.md` vira a base copiavel para novas perguntas.
- `content/challenges/README.md` passa a refletir o runtime real do Kodan.

## Recomendacoes futuras

- Se o question bank passar a alimentar o runtime automaticamente, formalizar um passo de promocao com validacao dedicada.
- Se surgirem mais tipos de pergunta, registrar primeiro no toolkit e gerar docs a partir dele, em vez de atualizar documentos manualmente.
- Quando quiser reativar o fluxo do `impeccable`, completar a pasta `.impeccable/` com os scripts e referencias exigidos pela skill.
